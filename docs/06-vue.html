1. 响应式的代价与依赖追踪

Vue 3 用 Proxy 实现响应式：get 拦截时收集依赖（谁在用这个属性），set 拦截时触发更新（通知这些地方重跑）。

两个决定性能的关键事实：

  1. 更新粒度是「组件级」：一个响应式数据变化，触发的是引用它的组件的渲染 effect 重跑（重新执行整个 <script setup> 的模板渲染），而不是只更新 DOM 上那一小格。组件越大、越重，一次更新的代价越大——拆组件就是拆更新范围。
  2. 深层响应式有代理成本：reactive() 会递归代理嵌套对象。给几万条的列表套深层响应式，光代理就吃掉可观内存与 CPU。
// 文件: 示例片段 —— 常见的响应性丢失坑（性能问题的伪装者）
import { reactive, toRefs } from 'vue';

// ❌ 解构 reactive 对象：解构出的变量断开响应式连接，后续更新视图不动
const state = reactive({ count: 0, user: {} });
let { count } = state;

// ✅ 用 toRefs 保持每个属性的响应式连接
const { count: countRef } = toRefs(state);

// ❌ reactive 整体替换：Proxy 代理的是原对象，重新赋值引用不会触发更新
state.user = { ...state.user, name: '新名字' }; // ✅ 改属性可以
// state = reactive({...})                      // ❌ 这样做不会更新视图

运行方式：Vue 3 项目内直接验证；配合 Vue DevTools 的「渲染高亮」观察组件更新范围。

2. 渲染控制：v-if v-show computed 与 v-memo

四个工具各管一件事，选错就是性能坑：

工具 机制 用在
v-if 条件为假时不渲染（切换有创建/销毁开销） 初始为假、切换少的场景
v-show 始终渲染，只切 display（初始开销大） 频繁切换的显隐（Tab、悬浮层）
computed 缓存：依赖不变直接返回上次结果 派生数据（过滤、排序、格式化）
v-memo 依赖数组不变时跳过整段子树渲染 大列表行、重组件的渲染热点 
<!-- 文件: src/components/GoodList.vue —— v-memo 与 computed 组合的标准写法 -->
<script setup>
import { computed, ref } from 'vue';
const props = defineProps({ items: { type: Array, default: () => [] } });
const selectedId = ref(null);

// computed 缓存派生数据：items 不变时反复访问零成本
const sorted = computed(() =>
  [...props.items].sort((a, b) => b.score - a.score)
);
</script>

<template>
  <!-- v-memo：依赖只有「是否选中」，未选中的行在 selectedId 变化时不再重渲染 -->
  <div v-for="item in sorted" :key="item.id" v-memo="[item.id === selectedId]">
    <span>{{ item.name }}</span>
    <span>{{ item.score }}</span>
    <button v-if="item.id === selectedId" @click="selectedId = null">取消</button>
  </div>
</template>

运行方式：Vue DevTools 开启渲染高亮，点击行切换选中，观察只有相关行重渲染。

⚠️ v-memo 的依赖数组必须覆盖模板中用到的所有响应式值，漏写会导致视图不更新——这是正确性问题，比性能问题更严重。

3. 大列表：虚拟滚动实战

千行级列表直接 v-for，DOM 规模会让滚动与更新双双崩溃（第 4 章第 7 节的原理）。Vue 生态用 vue-virtual-scroller：

npm install vue-virtual-scroller

<!-- 文件: src/components/BigTable.vue —— 动态行高虚拟滚动 -->
<script setup>
import { RecycleScroller } from 'vue-virtual-scroller';
import 'vue-virtual-scroller/dist/vue-virtual-scroller.css';
const items = await fetchHugeList(); // 1 万条也只渲染可视区约 20 条
</script>

<template>
  <RecycleScroller
    class="scroller"
    :items="items"
    :item-size="56"
    key-field="id"
    v-slot="{ item }"
  >
    <div class="row">{{ item.name }} · {{ item.score }}</div>
  </RecycleScroller>
</template>

运行方式：项目内使用；行高不固定用 DynamicScroller。对比改造前后的 DOM Elements 面板节点数。

配套细节：行组件内配合 v-memo（本章第 2 节）；列表数据如果是服务端一次性下发的大 JSON，先做分页/分片（第 5 章第 3 节）。

4. 组件复用与 KeepAlive

路由切换回来要重发请求、重建组件？<KeepAlive> 缓存组件实例（连同组件状态），切回来直接复活：

<!-- 文件: src/layouts/Main.vue —— KeepAlive 控制缓存范围与数量 -->
<template>
  <RouterView v-slot="{ Component }">
    <KeepAlive :include="['Report', 'Dashboard']" :max="10">
      <component :is="Component" />
    </KeepAlive>
  </RouterView>
</template>

三条纪律：

  1. 必须配 include 白名单或 max：无界缓存 = 内存泄漏温床（每个缓存实例连同其数据常驻）；
  2. 被缓存的组件用 onActivated/onDeactivated 代替 onMounted/onUnmounted 做数据刷新与清理；
  3. 含大量状态或定时器的组件不适合缓存，宁可重挂载。

5. 按需加载：路由分割与组件库按需引入

路由级分割（Vite 脚手架默认支持，确认每条路由都是动态 import，见第 3 章第 8 节）。

组件库按需引入：Element Plus 全量引入约 1MB+，按需引入后只打包用到的组件：

// 文件: vite.config.ts —— Element Plus 自动按需（unplugin 系列）
import AutoImport from 'unplugin-auto-import/vite';
import Components from 'unplugin-vue-components/vite';
import { ElementPlusResolver } from 'unplugin-vue-components/resolvers';

export default defineConfig({
  plugins: [
    AutoImport({ resolvers: [ElementPlusResolver()] }),
    Components({ resolvers: [ElementPlusResolver()] }),
    // 模板里直接写 <el-button>，构建时只引入对应组件与样式
  ],
});

运行方式：npm run build 对比引入前后的产物体积（本例通常减少 60% 以上）。

重型库按需：echarts 用 echarts/core 注册用到的图表与组件，避免整包引入；大工具函数库改用子路径引入（lodash-es/debounce）。

6. 状态管理：Pinia 的性能姿势

Pinia 本身开销极小，性能问题出在存了什么、怎么存：

// 文件: src/stores/feed.js —— 大数据量 store 的正确姿势
import { defineStore } from 'pinia';
import { shallowRef, triggerRef } from 'vue';

export const useFeedStore = defineStore('feed', () => {
  // ❌ 反例：ref(hugeList) 深层响应式——每条数据都被 Proxy 代理
  // ✅ 正解：shallowRef 只代理数组引用本身，内部元素保持原始对象（零代理成本）
  const list = shallowRef([]);

  function replaceAll(next) {
    list.value = next;        // 整体替换引用，天然触发更新
  }
  function patchOne(id, patch) {
    const i = list.value.findIndex((x) => x.id === id);
    if (i < 0) return;
    list.value[i] = { ...list.value[i], ...patch };
    triggerRef(list);         // 手动通知：原地改内容时需显式触发
  }

  // getters 自动缓存（依赖不变不重算），适合放派生统计
  const total = (state) => state.list.length;
  return { list, replaceAll, patchOne, total };
});

运行方式：Pinia 项目内验证；用 Vue DevTools Timeline 观察 store 更新触发的组件范围。

原则：store 存「跨组件共享的必要状态」，组件私有状态留在组件内；巨型 store 按业务域拆分（每个 store 是独立更新单位）。

7. 响应式降耗：shallowRef 与 markRaw

两类「不该被代理」的数据，用两个 API 免除代理成本：

API 场景 效果
shallowRef 大数组/大对象（列表、表格数据、图表数据集） 只有 .value 赋值触发更新，内部不代理
shallowReactive 对象只需顶层响应式 嵌套属性不代理
markRaw 第三方实例（echarts 实例、地图实例、class 实例） 永久标记「永不代理」，塞进 reactive 也不被转 
// 文件: src/composables/useChart.js —— markRaw 的经典场景
import { shallowRef, markRaw, onUnmounted } from 'vue';
import * as echarts from 'echarts/core';

const chart = shallowRef(null);

function init(el) {
  // 图表实例绝不需要响应式：markRaw 防止它被 Proxy 包裹（避免奇怪 bug + 省内存）
  chart.value = markRaw(echarts.init(el));
  window.addEventListener('resize', chart.value.resize, { passive: true });
}
onUnmounted(() => window.removeEventListener('resize', chart.value.resize));

运行方式：Vue 项目内使用；开启响应式转换调试（app.config.warnAboutReactiveLoss）可发现被误代理的实例。

8. 构建与产物优化

Vue 项目的产物优化清单（配合第 3 章通用手段）：

// 文件: vite.config.ts 片段 —— 第三方稳定依赖分包，提升缓存命中
export default defineConfig({
  build: {
    rollupOptions: {
      output: {
        // vue 全家桶与 echarts 变更少，单独分包后业务迭代不影响它们的缓存
        manualChunks: {
          vue: ['vue', 'vue-router', 'pinia'],
          charts: ['echarts'],
        },
      },
    },
  },
});
  • npm run build 后用 rollup-plugin-visualizer 审查包构成，处理重复依赖
  • 路由级分割全量覆盖（除首页外的页面全部动态 import）
  • 组件库/重型库按需引入，体积对比记录在案
  • 第三方稳定依赖 manualChunks 分包
  • 产物 Brotli 预压缩，静态资源上 CDN
  • 建立体积预算（如 JS ≤ 170KB 压缩后）并接入 CI（第 9 章）

9. 最佳实践清单

  • 组件合理拆分，缩小每次响应式更新的重渲染范围
  • 派生数据一律 computed；渲染热点用 v-memo（依赖数组写全）
  • 显隐切换按频率选 v-if/v-show，不凭感觉
  • 千行级列表上虚拟滚动，行组件配合 v-memo
  • KeepAlive 必带 include/max，缓存组件用激活钩子做刷新与清理
  • 大数据进 store 用 shallowRef；第三方实例 markRaw
  • 组件库与重型依赖按需引入，产物体积有预算有门禁
