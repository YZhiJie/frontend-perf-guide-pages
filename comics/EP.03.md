# EP.03 · 《餐厅备菜大作战》

> 🎬 漫画：[EP.03.svg](./EP.03.svg) ｜ 📄 对应文档：[第 3 章 · 加载性能优化：网络与资源](../docs/03-loading.md)
>
> 本话主旨：把页面加载类比餐厅备菜——少加载、早加载、按需加载，40 分钟上菜变 8 分钟。

## 本话剧情

小奔接手一家「灾难餐厅」：每道菜都现从城外拉食材（无缓存无压缩）、一本厚菜单包揽所有菜品（无代码分割）、客人点啥才手忙脚乱现做（无预热）。稳叔三板斧治理：菜就近备（CDN）、半成品预制（压缩+缓存）、热门菜提前做（preload）；再把厚菜单拆页（代码分割）、配菜按需做（懒加载）。上菜时间从 40 分钟压到 8 分钟。

## 知识点节点

### 节点 1 · 关键路径阻塞：灾难厨房的根源（漫画第 1 格）

- **生活映射**：样样现拉、层层等待 = 阻塞渲染的 CSS/JS 串成一条长队，首屏迟迟出不来。
- **技术对应**：CSS 阻塞渲染、默认 script 阻塞解析；defer/async 是解药，关键 CSS 内联是捷径。
- **深入阅读**：📖 [1. 关键渲染路径：浏览器拿到 HTML 之后](../docs/03-loading.md#1-关键渲染路径浏览器拿到-html-之后)

### 节点 2 · 稳叔三板斧：CDN、压缩缓存、连接预热（漫画第 2 格）

- **生活映射**：菜就近备（边缘节点）、半成品预制（压缩+强缓存）、热门菜提前做（preconnect/preload）。
- **技术对应**：CDN 缩短物理距离；Brotli 再省 15~20%；hash 资源缓存一年；preconnect 省下握手时间。
- **深入阅读**：📖 [2. 网络层优化：CDN 与连接预热](../docs/03-loading.md#2-网络层优化cdn-与连接预热)、[3. 资源压缩与传输](../docs/03-loading.md#3-资源压缩与传输)、[7. 缓存策略设计](../docs/03-loading.md#7-缓存策略设计)

### 节点 3 · 拆菜单与按需做菜：代码分割与懒加载（漫画第 3 格）

- **生活映射**：厚菜单拆单页（路由级分割），配菜等点单再做（懒加载），上菜 8 分钟。
- **技术对应**：动态 import 按路由分包；图片 `loading="lazy"` + IntersectionObserver；Vue 路由懒加载 / React.lazy + Suspense。
- **深入阅读**：📖 [6. JavaScript 交付与代码分割](../docs/03-loading.md#6-javascript-交付与代码分割)、[8. 框架落地：路由分割与资源提示](../docs/03-loading.md#8-框架落地路由分割与资源提示)

### 节点 4 · 最大坑点：拆得太碎反而更慢（漫画第 4 格）

- **误区**：把代码拆成几百个小 chunk、几十张小图——HTTP/2 虽能多路复用，但请求调度开销与缓存粒度劣化会让小文件过多得不偿失。
- **正解**：路由级/重组件级适度分割；图片按 `srcset` 发合适尺寸；LCP 主图绝不懒加载。
- **深入阅读**：📖 [4. 图片优化：格式、响应式与懒加载](../docs/03-loading.md#4-图片优化格式响应式与懒加载)、[5. 字体加载策略](../docs/03-loading.md#5-字体加载策略)

## 常见认知误区

| 误区 | 真相 |
| --- | --- |
| 文件越小越好、拆越碎越快 | HTTP/2 下适度分割即可，过碎增加调度开销且伤缓存 |
| 所有图片都该懒加载 | 首屏 LCP 主图懒加载会直接拖慢 LCP |
| gzip 一开就万事大吉 | 图片/字体已是压缩格式，二次压缩白费 CPU；首选 Brotli 预压缩 |

## 自测三题

**1. 关键渲染路径中，什么会阻塞首屏渲染？**

A. 图片　B. 同步 CSS 与阻塞脚本　C. 字体文件

> 答案：B。CSS 阻塞渲染，同步脚本阻塞 HTML 解析。

**2. 静态资源长期缓存的关键做法是？**

A. 文件名带内容 hash + 长 max-age　B. 每次发版换目录　C. 关闭缓存

> 答案：A。内容变则文件名变，未变则永久命中缓存。

**3. preconnect 与 preload 的区别是？**

A. 前者提前建立连接，后者提前拉取具体资源　B. 完全相同　C. 前者拉资源，后者建连接

> 答案：A。preconnect 省握手，preload 提前下载关键资源。

## 一句话带走

**少加载（分割与按需）、早加载（预热与优先级）、按需加载（懒加载）——先减少量，再优化时序。**
