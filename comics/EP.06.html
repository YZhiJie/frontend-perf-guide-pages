EP.06 · 《Vue 后厨的智慧》

🎬 漫画：EP.06.svg ｜ 📄 对应文档：第 6 章 · Vue 专项优化方案

本话主旨：Vue 的性能之道——让组件少算、缓存、按需渲染。

本话剧情

小奔到 Vue 餐馆后厨观摩，目睹灾难：客人只加一碗米饭，厨师却把整桌菜重做一遍（组件级重渲染粒度）。稳叔亮出后厨智慧：computed 是备好的半成品（依赖不变直接端出），v-if 是「不做不上桌」而 v-show 是「做好盖盖子」，菜单拆页按需上（路由懒加载），常客老位置留着（KeepAlive），没变的菜直接端旧盘（v-memo）。最后踩坑：把几万条的大 JSON 全塞深层响应式，Proxy 逐层代理白耗 CPU。

知识点节点

节点 1 · 更新粒度是组件级（漫画第 1 格）

  • 生活映射：加碗饭重做整桌 = 一个响应式数据变化，触发整个组件重渲染，组件越大代价越大。
  • 技术对应：Proxy 依赖追踪 + 组件级 render effect；拆组件就是缩小更新范围。
  • 深入阅读：📖 1. 响应式的代价与依赖追踪

节点 2 · computed 是半成品，v-memo 是旧盘直端（漫画第 2 格）

  • 生活映射：半成品不用每次现做（computed 缓存）；没变的菜端旧盘（v-memo 跳过子树渲染）。
  • 技术对应：computed 缓存派生数据；v-memo 依赖数组不变则跳过渲染；v-if/v-show 按切换频率选。
  • 深入阅读：📖 2. 渲染控制：v-if v-show computed 与 v-memo

节点 3 · 拆菜单与常客座位：按需加载与 KeepAlive（漫画第 3 格）

  • 生活映射：厚菜单拆单页（路由级分割）；常客老位置留着（KeepAlive 缓存组件实例）。
  • 技术对应：动态 import 按路由分包；组件库按需引入（unplugin 系列）；KeepAlive 必须配 include/max。
  • 深入阅读：📖 3. 大列表：虚拟滚动实战、4. 组件复用与 KeepAlive、5. 按需加载：路由分割与组件库按需引入

节点 4 · 最大坑点：大数据全塞深层响应式（漫画第 4 格）

  • 误区：ref(hugeList) 深层响应式——几万条数据被 Proxy 逐层代理，白白吃掉内存与 CPU。
  • 正解：大数组用 shallowRef + 整体替换；第三方实例（echarts/地图）用 markRaw 标记永不代理。
  • 深入阅读：📖 7. 响应式降耗：shallowRef 与 markRaw、6. 状态管理：Pinia 的性能姿势

常见认知误区

误区 真相
Vue 是响应式框架，性能不用操心 更新粒度是组件级，重组件滥用照样卡
v-show 一律优于 v-if 频繁切换才用 v-show；初始为假的块用 v-if 更省
KeepAlive 无脑包路由 无界缓存等于内存泄漏温床，必须 include/max

一句话带走

让组件少算（拆分与 computed）、缓存（v-memo 与 KeepAlive）、按需渲染（v-if 与懒加载）——Vue 优化的本质是缩小更新范围。
